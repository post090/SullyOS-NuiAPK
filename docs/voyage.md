# 旅迹

桌面入口、邀请信和回信随用户空间保存。角色接受后，用户可以把选定的旅行简报送到自己的策划服务，再决定是否采纳草稿。所有活动都是虚拟旅行。送邀请和批准计划都不扣款。

## 策划服务

独立部署 `worker/voyage`。D1 保存账户、申请、草稿版本及投递记录，KV 保存 OAuth 授权。已有主代理和主动消息 2.0 各自继续使用原配置。

1. 在仓库根目录运行 `pnpm install`。进入 `worker/voyage` 后，在自己的 Cloudflare 账户创建一个 D1 数据库和一个 Workers KV 命名空间。
2. 从 `wrangler.example.jsonc` 复制出本机的 `wrangler.jsonc`，填写自己的服务名、D1 名称与资源 ID、KV ID。保留严格公网出站标志。以下命令从这个目录运行。
3. 运行 `pnpm dlx wrangler@4.168.0 d1 execute DB --remote --file schema.sql` 创建表。在仓库外选一个新的私有目录，执行 `pnpm exec node enroll.mjs <私有目录>`，再执行 `pnpm dlx wrangler@4.168.0 d1 execute DB --remote --file <私有目录>/enroll.sql`。每个独立账户使用一组新配对码。
4. 运行 `pnpm dlx wrangler@4.168.0 deploy`。从密码管理器生成的 32 字节随机值取标准 Base64，作为 `pnpm dlx wrangler@4.168.0 secret put EVENT_ENCRYPTION_KEY` 的输入。这是服务级密钥，续用同一服务时保留原值。
5. 在 ChatGPT 网页的「插件 → ＋ → 添加自定义 MCP 服务器」填入服务的 HTTPS `/mcp` 地址。选择 OAuth，在高级设置中选择动态客户端注册，申请 `travel:plan` 和持续运行所需的 `offline_access`。创建私有插件并点「继续连接」，在跳出的「连接旅行策划」页面输入 `dot-pairing.txt` 里的码。已有可读取旅行申请的连接可直接复用。SullyOS 的「旅行策划」使用同一服务的根地址和另一份 `device-pairing.txt` 配对码。

## 第一次联调

在选定的 Dot 中启用插件，让它订阅 `trip.requested`。约定收到申请后调用 `get_trip_request`，按简报查询目的地、开放条件、当地天气与天气备选，通过 `submit_draft` 按当前版本交稿。出发日尚远时列季节资料和来源；临近出发再查带日期的预报。角色自己的模型决定实际感受、同行者和行动。

「Dot 已订阅」来自当前账户有效的事件订阅。Webhook 成功只代表投递到达。收到与申请编号对应的版本化草稿，才能确认 Dot 完成了工作。如果 Dot 没有该事件入口，可以在已授权的对话中让它主动查看待办并交稿；这种方式需要手动发起。

排查订阅时，先看已连接插件的「事件」中有没有 `trip.requested`，再核对 Dot 已保存的任务。服务维护者可以用 `pnpm dlx wrangler@4.168.0 tail --search voyage.events --format pretty` 观察一次订阅过程。`events/list` 表示 ChatGPT 读取了事件目录，`events/subscribe received` 表示请求到达，`saved` 表示回调验证通过并已保存。回调必须直接返回成功状态和原挑战值。诊断消息仅含阶段、固定原因和回调 HTTP 状态，省略回调地址、密钥和申请内容。

## 数据与审批

- 申请只携带不透明编号和用户最终确认的简报。设备配对码只保留在当前用户的会话内。用户手写的私信、模型凭据、完整人设和聊天历史都不随申请传送。
- 草稿走「等待策划 → 等你审核 → 已批准」。退回会保留该版、记录意见并通知 Dot。审批必须提供审核时所见的版本与摘要，客户端刷新后才能审阅新版。设备负责审批，策划插件只能提交草稿。
- 送信及回信分别与相应私聊消息在同一笔本机事务内提交。已批准行程保存在邀请上，离线可查。文字与完整备份保留记录，媒体补档沿用现有匹配规则。迁入独立用户后重新匹配新角色，云端申请编号也随之隔离。
- 签名事件只包含申请编号。失败投递在刷新和低频服务端重试时处理，同一事件沿用相同编号。后台重试只投递已有申请，不调用角色模型。

## 运行边界

亲手送信不调用模型；点「请对方回信」通常发起一次角色生成，启用的记忆召回按该角色现有设置工作。查订阅、拉取和批准均为普通数据请求。Dot 对真实资料的调查由用户连接的官端任务承担。

全天离线按目的地时区推进旅行是后续阶段。需要在主动消息 2.0 的云端执行器接入已批准的分时日程、角色授权、幂等经历与返程恢复。当前阶段，批准行程不会覆盖既有日程或把未来活动写成已发生的记忆。相册、纪念品入库及实际消费结算均留到执行阶段。
